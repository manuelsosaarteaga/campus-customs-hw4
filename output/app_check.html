02Dynamic search result cards on the page

Goal: asking about a category in chat makes the agent search the catalogue and the site show the matching products as cards, and each card opens the single-item view.

How the cards get to the page

1. Agent calls search_products → returns AgentReply {message, product_ids, results_title: "Hoodies"}.

2. Backend rebuilds each card from SQLite (ProductCard: id, name, price, image, colors, available sizes) and drops any id the tools didn't return.

3. React stores them in shared state and renders the same ProductCard link used on the Shop page, so each one opens /products/{id}.

DB check: SELECT COUNT(*) FROM catalogue WHERE garment_type LIKE '%hood%' → 27.

03Usability feature: typo-tolerant search

Goal: one of the Problem 9 upgrades working on the live site. Misspelled college, sport, and garment names still find products, both in the Shop search box and in chat.

All four Problem 9 upgrades

Front end: context-aware quick-reply buttons · stock badges on every card.

Backend: typo-tolerant search (shown here) · graceful failure (timeouts and retries, plus database fallback cards and a "Try again" button when the AI is down).

Details and full test results: output/usability.md.

How to reproduce

  1. Backend: cd backend && uvicorn main:app --reload --port 8000 (needs PORTKEY_API_KEY and data/campus_customs.db).
  2. Frontend: cd frontend && npm install && npm run dev, then open http://localhost:5173.
  3. Check 1: open the Baseball Left Chest Crewneck page → chat Do you have this in XL? And how much is it?
  4. Check 2: Home → chat What hoodies do you have? → click any card.
  5. Check 3: Shop → type saybrok in the search box.
